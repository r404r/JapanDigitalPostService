# UI 利用ガイド

言語: [中文](README.md) | [日本語](README.ja.md) | [English](README.en.md)

このガイドは手動テストと日常確認を目的として、React sample 画面の主な操作手順を説明します。スクリーンショットは固定のサンプルデータで撮影しており、操作位置を示すためのものです。実際の実行時には、住所、時刻、token 一覧はデータベースの内容に応じて変わります。

## 1. 画面を開く

推奨は、全機能入りの手動テストコンテナで起動する方法です。

```bash
docker compose -f deployments/manual-test.compose.yml up -d --build
```

ブラウザーで `http://localhost:8080` を開きます。手動テスト用の既定 admin token は `deployments/manual-test.env` で次のように設定されています。

```text
jdps_manual_admin_token
```

画面右上の `Bearer token` 入力欄には token 本体だけを入力し、`Bearer ` プレフィックスは入力しません。フロントエンドは token をブラウザーの `sessionStorage` にのみ保存するため、そのブラウザーセッションを閉じた後は再入力が必要です。

現在の `deployments/manual-test.env` では、AES-GCM 手動テスト用にアプリケーション層レスポンス暗号化を有効にしています。

```text
PAYLOAD_ENCRYPTION=aes-gcm
PAYLOAD_ENC_KEY=MDEyMzQ1Njc4OWFiY2RlZjAxMjM0NTY3ODlhYmNkZWY=
PAYLOAD_ENC_KEY_ID=manual-test
```

画面右上の `API 暗号化 key` 入力欄には、同じ base64(32B) `PAYLOAD_ENC_KEY` を入力します。フロントエンドはレスポンスヘッダーが `X-Payload-Encryption: AES-256-GCM` のとき、JSON エンベロープを自動的に復号します。この key も現在のブラウザーの `sessionStorage` にのみ保存されます。バックエンドを `PAYLOAD_ENCRYPTION=none` に戻した場合、この入力欄は空のままで構いません。

フロントエンド開発時は、Vite だけを個別に起動することもできます。

```bash
npm install --prefix web
npm run dev --prefix web
```

Vite 画面は既定で `http://localhost:5173` に表示され、`/v1` 経由でローカルの `:8080` バックエンドへプロキシします。

## 2. Token と権限

| scope | 利用できる画面/操作 | 説明 |
|---|---|---|
| `read` | 住所検索、同期状態の取得、同期履歴の取得 | 読み取り専用の検索ユーザー向け。 |
| `admin` | `read` の全機能、手動同期、token 発行、token 一覧、token 失効 | 管理操作向け。 |

よく使うルール:

- 検索ページでは `read` または `admin` token を使用できます。
- 管理ページで同期状態/履歴を読む場合は `read` または `admin` token を使用できます。
- 管理ページで同期を実行する、token を発行する、token 一覧を見る、token を失効する操作には `admin` token が必要です。
- 新規発行した token の平文は作成直後に一度だけ表示されます。閉じる、または非表示にした後は復元できないため、既存の admin token で再発行してください。

## 3. 住所検索

「検索」tab に入ると、郵便番号、都道府県、市区町村、キーワードを組み合わせて検索できます。少なくとも 1 つの条件を入力してから「検索実行」をクリックします。

![住所検索結果](assets/search-results.png)

結果エリアの意味:

| 項目 | 意味 |
|---|---|
| `total_count` | バックエンドで条件に一致した総件数。 |
| `returned` | 今回のレスポンスで返された件数。API の `returned_count` に対応します。 |
| `items.length` | フロントエンドが実際に受け取った住所配列の長さ。通常は `returned` と一致します。 |
| 結果表 | 郵便番号、都道府県、市区町村、町域、カナを表示します。 |

状態表示:

- `検索条件を1つ以上入力してください。`: 検索条件が未入力です。郵便番号、都道府県、市区町村、キーワードのいずれかを入力してください。
- `too_many_results`: 条件が広すぎ、サーバー側のしきい値を超えています。検索条件を絞ってください。
- `timeout`: 検索が時間上限を超えました。検索条件を絞るか、バックエンド負荷を確認してください。
- `0 件`: リクエストは成功しましたが、一致する住所がありません。
- `401`: token が未入力、または token が無効/期限切れです。
- `403`: token は有効ですが権限が不足しています。

## 4. 同期管理

「管理」tab に入ると、上半分が同期管理です。ここでは「状態確認」と「手動同期」が別々の領域に分かれており、プルダウンの適用範囲を誤解しにくくしています。

![同期管理](assets/admin-overview.png)

左側の「状態を更新」:

- 「状態を再読込」は現在の同期状態と最新 100 件の同期履歴だけを再取得します。
- このボタンは右側の「同期方式」プルダウンの影響を受けません。

右側の「同期を開始」:

- 先に「同期方式」を選択し、その後「選択した方式で同期実行」をクリックします。
- プルダウンはこの同期実行ボタンだけに影響します。

同期方式:

| 方式 | 意味 |
|---|---|
| `auto` | バックエンドが自動判定します。データベースが空なら full、それ以外は diff。 |
| `full` | 全量同期を強制します。 |
| `diff` | 差分同期を強制します。 |

状態カード:

| 項目 | 意味 |
|---|---|
| `total_addresses` | 現在の住所マスタ件数。 |
| `running` | 同期が実行中かどうか。 |
| `last_type` | 直近の成功した同期タイプ。 |
| `last_success_at` | 直近の成功した同期完了時刻。 |

同期履歴:

- 永続化された同期記録の最新 100 件を表示します。
- ブラウザー更新後も、token がある場合はバックエンドから再取得します。フロントエンドのメモリには依存しません。
- `processed` は今回処理した行数、`skipped` は町域名フィルター正規表現でスキップした行数、`error` は失敗概要を示します。成功時は通常 `-` です。
- 同期履歴は 1 ページ 6 行表示です。表の下の「前へ」/「次へ」でページを切り替えます。
- `skipped` が 0 より大きい場合、数字の後ろに「照会」ボタンが表示されます。クリックすると「除外行明細」モーダルが開き、その同期のフィルター明細を確認できます。
- フィルター明細は 1 ページ 100 件ずつ取得します。「前へ」/「次へ」でページを切り替え、ウィンドウ下部に現在のページ数が表示されます。
- 明細表には source、line、zipcode、prefecture / city / town、town_kana、pattern、raw が含まれます。`raw_record_json` は既定で省略表示され、「raw を表示」をクリックすると完全な JSON を展開し、「raw を隠す」で折りたたみます。

### 4.1 取得/インポート設定（リトライ回数 / 全量 URL / 町域名フィルター）

取得/インポート動作はオンラインで設定でき、**再起動後も保持**されます。

- **ネットワークリトライ回数**（`download_max_retry`、既定 `3`）: 日本郵便サイトからデータを取得するときにネットワーク問題が発生した場合の追加リトライ回数です。有効範囲は 0 から 10 です。
- **全量取得 URL**（`scrape_full_url`、既定 = 設定ファイル内の公式全量 URL）: 日本郵便公式ドメイン（`post.japanpost.jp`）配下の別の https URL に変更できます。「復元」操作で既定 URL に戻せます。
- **町域名フィルター正規表現**（`town_skip_regex`、既定は空）: 町域名でインポート行を判定し、命中した行は住所マスタに書き込まず、フィルター明細へ記録します。この項目はバックエンドの Go 正規表現で検証され、フロントエンドの JavaScript 正規表現で事前に保存を止めることはありません。
- 優先順位: 管理画面設定（DB に永続化）> 環境変数 > コード既定値。変更は**次回の同期**（自動スケジュール / 手動実行 / `cmd/batch`）から有効になり、再起動は不要です。
- URL / 正規表現の検証、エラー表示、保存成功表示はいずれも日本語です。https ではない URL、公式ドメイン外の URL、不正な Go 正規表現は拒否されます。

画面操作:

1. 「リトライ回数」に 0 から 10 の整数を入力します。範囲外、または整数でない場合は「リトライ回数は 0 以上 10 以下の整数で指定してください。」と表示され、保存されません。
2. 「全量取得 URL」に日本郵便公式ドメイン（`post.japanpost.jp` / `www.post.japanpost.jp`）の https URL を入力します。https ではない URL、または公式ドメイン外の URL は日本語のエラー表示で拒否されます。
3. 「町域名フィルター」に町域名フィルター用の Go 正規表現を入力します。空のままにするとフィルターは無効です。バックエンド検証に失敗した場合、画面に「町域名フィルターの正規表現が正しくありません。」と表示されます。
4. 「保存」をクリックすると、成功時に「設定を保存しました。」と表示されます。DB に保存された値は以後の同期またはアップロード取り込みに使用されます。
5. 「既定値に戻す」をクリックすると、`download_max_retry`、`scrape_full_url`、`town_skip_regex` の上書き値が削除され、既定値に戻ります。

バックエンド API: `GET /v1/admin/settings` / `PUT /v1/admin/settings`（どちらも `admin` token が必要。契約は [`docs/api/v1.md`](../api/v1.md) を参照）。

### 4.2 ファイルアップロード

「ファイルアップロード」では、日本郵便 `utf_ken_all` の zip または UTF-8 csv を全量同期としてインポートできます。

1. `.zip` または `.csv` ファイルを「zip/csv をドラッグ、またはクリックして選択」へドラッグ&ドロップします。この領域をクリックしてファイル選択ダイアログから選ぶこともできます。
2. 対応していない拡張子の場合は「zip または csv ファイルを選択してください。」と表示され、アップロードできません。
3. ファイルを選択したら「アップロード実行」をクリックします。実行中はボタン文言が「アップロード中」になります。
4. 成功後、全量同期の実行結果が画面に反映され、状態と「同期履歴」が再取得されます。
5. 失敗時はバックエンドから返された日本語メッセージが表示されます。たとえば Shift-JIS 版など UTF-8 ではない `utf_ken_all` CSV は「UTF-8 の utf_ken_all CSV のみ対応しています。Shift-JIS 版は利用できません。」と表示されます。

## 5. Token 管理

「Token 管理」は管理ページの下半分にあり、`admin` token が必要です。

![Token 発行](assets/token-created.png)

token の発行:

1. 「名前」に用途を入力します。例: `frontend-read`。
2. `scope` で `read` または `admin` を選択します。
3. 「発行」をクリックします。
4. 「保存してください」領域で平文 token をコピーし、安全な場所に保存します。

Token 一覧:

- `prefix` は識別用のマスク済み前置部分であり、完全な token ではありません。
- `scope` は権限を示します。
- `last_used` は直近の使用時刻です。未使用の場合は `-` です。
- `revoke` はその token を失効します。失効後は復元できません。

## 6. トラブルシューティング

| 現象 | 対処 |
|---|---|
| 画面に `401` が表示される | 右上に token 本体を入力済みで、`Bearer ` プレフィックスを入力していないことを確認します。 |
| 画面に `403` が表示される | 現在の token の権限が不足しています。同期実行と token 管理には admin token が必要です。 |
| 同期トリガーが `sync_running` を返す | 既に同期が実行中です。終了を待ってから「状態を再読込」をクリックします。 |
| 「町域名フィルター」の保存に失敗する | 入力が Go 正規表現であることを確認します。たとえば Go が対応する `(?i)町域` は保存できます。不正な書き方ではバックエンドから返る日本語エラーが表示されます。 |
| 同期履歴に「照会」がない | その run の `rows_skipped` が 0 です。実際にインポート行をスキップした run にだけフィルター明細の入口が表示されます。 |
| 検索結果が多すぎる | 郵便番号、都道府県、市区町村、またはキーワードの条件を追加してください。 |
| 新規 token の平文を失った | サーバーは hash だけを保存するため、復元できません。既存の admin token で再発行してください。 |
| 更新後に Bearer token が消える | token は `sessionStorage` に保存されています。新しいブラウザーセッションでは再入力が必要です。 |
| 画面に AES-GCM key が必要と表示される | バックエンドが暗号化レスポンスを返しています。`API 暗号化 key` に base64(32B) `PAYLOAD_ENC_KEY` を入力済みで、現在のバックエンド key と一致していることを確認します。 |

本番環境での注意:

- 手動テスト用の既定 token は使用しないでください。
- 本番の bootstrap admin token は `ADMIN_BOOTSTRAP_TOKEN` を使い、安全な環境変数または key 管理システムから注入してください。
- 実際の token や `PAYLOAD_ENC_KEY` をイメージレイヤー、README、スクリーンショット、commit 履歴に書き込まないでください。
