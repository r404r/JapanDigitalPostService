# task-0005 — 地址检索 API（实现记录）

> 状态: 已实现（读路径）。规划见 [`task-0005-query-api.md`](./task-0005-query-api.md)；
> 对外行为以 [`../spec.md`](../spec.md) §3.2/§3.3 与 [`../../api/openapi.yaml`](../../api/openapi.yaml) 为准。

## 交付范围

实现地址检索读路径，满足邮编精确查询与名称模糊查询：

- `GET /v1/addresses` — 按 `zipcode`/`prefecture`/`city`/`q` 检索；模糊最多 `FUZZY_LIMIT`（默认 20）条，返回 `total_count` / `returned_count` / `truncated`。
- `GET /v1/addresses/{zipcode}` — 按 7 位邮编精确查询，返回该邮编全部町域并标记 `address_count`；零命中 → `not_found`/404。
- 统一状态语义：`ok` / `too_many_results`（>`MAX_TOTAL`）/ `timeout`（504）/ `invalid_request`（400）/ `not_found`（404）。
- 超时贯穿 handler → service → repository → DB 驱动：handler 用 `QUERY_TIMEOUT` 建 `context.WithTimeout`，逐层透传；到时驱动中止查询并归还连接，绝不让请求无限占用 DB 连接。
- 每请求 `X-Request-Id`（trace id）回写响应头，错误体附带 `trace_id`。

## 关键决策

- **DB 驱动**：引入 `modernc.org/sqlite`（纯 Go，无 CGO）经 `database/sql` 接入，以便用真实 SQLite 跑 fixture 并真正验证「ctx 超时贯穿 DB 驱动」。
  - **版本锁定 `v1.23.1`**：更高版本的 `go.mod` 要求 go ≥ 1.23/1.25，会触发工具链下载、破坏仓库 `go 1.22` 基线；`v1.23.1`（go 1.18 directive）与基线兼容，不触发工具链切换。待 task-0002 升级工具链 / 引入 GORM 多方言时再评估升级。
  - 业务逻辑只依赖 `domain.AddressRepository`，未来换 GORM/PG/MySQL 不影响 service 与 handler。
- **跨方言模糊检索**：一律 `LIKE`（PG/MySQL/SQLite 通用），`q` 以 OR 覆盖汉字与カナ列；方言特有 FTS（pg_trgm/ngram/FTS5）留作后续优化，接口不变。
- **占位认证**：`authPlaceholder` 中间件按 architecture 边界放行，task-0006 替换为真实 Bearer 校验。
- **本地启动数据**：`SEED_SAMPLE_DATA`（task-0005 期默认 `true`；与 task-0004 合流后默认 `false`，见 spec 变更记录）在 `addresses` 表为空时写入内置示例（含一个映射 3 个町域的邮编 `4980000`），令 `go run ./cmd/server` 即可查询；同步引擎（task-0004）落地后于生产关闭。

## 测试

- `internal/query`：service 各分支（invalid / ok+truncated / 零命中 / too_many / limit clamp / timeout（ctx 取消 + repo 错误）/ internal_error / 邮编多地址 address_count / not_found）。

- `internal/server`：httptest 契约测试 —— health、邮编/模糊查询、invalid（无参/坏 limit）、too_many、邮编精确多地址 address_count、not_found、坏邮编、504 超时、`X-Request-Id` 头。

## 验证

- `go build ./... && go vet ./... && gofmt -l .` 干净，`go test ./...` 全绿。
- 本地 `go run ./cmd/server` 启动后：`/v1/health` ok；`/v1/addresses/4980000` 返回 3 条 + `address_count=3`；`/v1/addresses?q=東京` 返回 5 条；无参 400；不存在邮编 404；响应带 `X-Request-Id`。

## 性能 / 索引

- `addresses` 上对 `zipcode`/`prefecture`/`city`/`town` 建索引（见 `internal/store` schema）。
- 邮编精确（`=`）与前缀（`LIKE 'p%'`）可命中 `zipcode` 索引；`prefecture`/`city` 前缀模糊部分可用索引，含 `%前缀` 与 `q` 跨字段 `%term%` 为全表扫描 —— 全量约 12.4 万行，扫描可控（architecture §6 风险登记），超大表后续按方言上 FTS。
- COUNT 与 SELECT 复用同一 WHERE，分页 `LIMIT/OFFSET`；单连接池匹配 SQLite 单写者模型。

## 剩余风险 / 后续

- 真实 PG/MySQL 方言行为（大小写/排序/字符集）需在 task-0002 的多方言矩阵中验证。
- `offset` 深翻页在大结果集上的代价；命中过多时建议收窄条件（已由 `too_many_results` 提示）。
- 认证未接入前 `401` 不会触发（契约已就位，task-0006 落地）。
